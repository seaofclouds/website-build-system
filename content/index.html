Markdown and HTML in, a static website out.

Use this template Read the docs

Makes you a new repo with a clean history, yours from the first commit.

Content is just files

Put a file in content and it's on the site at that path. Frontmatter opts each page into the rest — a template, a date, a draft flag — and a plain HTML file is copied straight through.

A vocabulary for writing

Build a page out of macros and includes: {{figure}} for images and video, {{aside}} for a note in the margin, {{index}} for a listing. Footnotes, syntax highlighting and linkable headings come with the markdown.

Layout is a class on <body>

Twelve columns and four page shapes: plain, wide, a navigation sidebar, a gutter for marginalia. Figures break the measure by name, and the styleguide demonstrates every class on one page.

It checks its own work

Every internal link, anchor and asset path is verified against the pages just generated, so renaming a heading someone linked to surfaces at build time instead of reaching a reader two years later.

Everything a site needs, already there

RSS, a sitemap, llms.txt, redirects, drafts, dark mode, and font subsetting that cuts a typeface down to the characters your site actually uses.

Edit it like your own code

Settings are constants at the top of one file. Adding a macro means adding a case to a switch. About 2,000 lines of commented TypeScript, run directly by bun, deno or node.

Replace a plank at a time until none of the original remains, and it's still your site's build system throughout.

`./site` builds the site, watches for changes, and serves it at `localhost:3000` with live reload. What you deploy is a folder of static files — [GitHub Pages, Cloudflare and Netlify](/docs/deployment/) are a build command and an output directory.
